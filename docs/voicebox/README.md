# Voicebox: локальный голосовой пилот

27 октября 2026. Ветка: `integration/voicebox-local-first`.

Первый этап реализован как отдельная локальная служба Voicebox с Astel-адаптером. На Mac установлены зависимости, скачан Qwen3-TTS Base 0.6B, проверены загрузка модели через Metal, REST и настоящий MCP discovery/read. Это **API-служба, а не установленное desktop-приложение с окнами**. Из предоставленной владельцем записи создан профиль `Oleh RU` и получена первая русская проба длительностью 5,68 секунды. Владелец подтвердил, что узнаёт свой голос в этой пробе; позднее выбрал отдельный английский reference как основу английского голоса. Длинная речь и общая готовность к production пока не приняты; темп и чёткость английской речи ещё уточняются.

В первом реальном пилоте два присланных M4A совпали побайтово. Исходник оказался тихим, без цифровой перегрузки; для рабочей копии применены только линейное усиление и mono PCM 24 kHz. Выбран фрагмент 10,05 секунды. Текст и временные границы проверены локальным `mlx-whisper==0.4.3` с pinned Whisper Small checkpoint; transcript остаётся кандидатом до проверки владельцем. Распознавание синтезированной пробы передало почти весь тестовый текст с одной заменой слова; это не оценка голосового сходства. Аудио, profile binding, transcript и подробные отчёты сохранены в исключённых из Git `input/voicebox` и `output/voicebox`.

После подтверждения узнаваемости русского примера выполнена английская проба тем же `Oleh RU` reference: 9,04 секунды, Qwen Base 0.6B, `language=en`. Локальное распознавание передало текст с расширением сокращения `we're` в `we are`; цифровой перегрузки нет. Владелец узнаёт себя и на английском; уточнённая цель — более плавная английская речь с менее выраженным русским акцентом. Проба сохранена как baseline. В текущем MLX Base-пути нет работающего управления акцентом через `instruct`, и замедление аудио само по себе не меняет произношение. Полная повторная русская начитка сейчас не требуется.

Получена отдельная английская запись длительностью 30,272 секунды. Выбран фрагмент 14,3 секунды по фактической расшифровке записи и создан отдельный `Oleh EN`, сохранив `Oleh RU`. При том же тестовом тексте, модели 0.6B, seed 42 и остальных настройках выполнен `pilot-003-en` (B): 11,12 секунды, текст восстановлен распознаванием без расхождений после нормализации сокращений. Для A/B созданы отдельные копии с целевой громкостью -21,02 LUFS, применено только линейное усиление/ослабление. Скорость и высота тона в этом сравнении не менялись; оригинальные WAV и RAW сохранены. Владелец узнаёт свой голос в B и выбрал английский reference как основу, попросив немного ускорить и сделать речь чище. Это приёмка основы короткой пробы, а не полного произношения или production.

В `mastering-001` сохранена отдельная проба C из B: темп ×1,08 и мягкий high-pass 60 Hz, без спектрального шумоподавления, новой TTS-генерации или правки reference. Это обработка темпа и низкочастотной составляющей; фонетический акцент она не исправляет. C длится 10,29 секунды; громкость копий B/C измерена как -21,06/-21,02 LUFS, цифровой перегрузки нет. Локальный ASR восстановил весь текст после нормализации сокращений. Владелец узнаёт себя в C, но по-прежнему считает темп слишком медленным.

Следующее сравнение `mastering-002`: D ×1,15 (9,67 секунды) и E ×1,25 (8,89 секунды) относительно исходной B, с тем же high-pass и выровненной громкостью -21,03 LUFS. Обе пробы созданы непосредственно из B; ускорения не наслаивались. ASR восстановил весь текст обеих проб после нормализации сокращений, цифровой перегрузки нет. Исходные B/C сохранены с проверкой SHA-256. Предпочтительный темп и естественность D/E ожидают прослушивания владельцем; более высокий темп не считается автоматически принятым. Подробные настройки, контрольные суммы и отдельные feedback receipts находятся вместе с приватными WAV вне Git.

По запросу владельца создана F в `mastering-003`: ×1,20 относительно исходной B, 9,27 секунды, тот же high-pass и -21,02 LUFS. Владелец подтвердил узнаваемость голоса и совпадение скорости с привычной речью, приняв F как предварительную рабочую основу английского голоса. Для следующих проб отправная точка — `Oleh EN` и обработка темпа ×1,20; это отдельная обработка WAV, а не параметр скорости модели. Приёмка относится к этой короткой пробе. Более длинная речь и устойчивость результата на других текстах ещё требуют проверки.

Выполнен `pilot-004-en-long`: новый вымышленный тестовый рассказ из 169 слов, `Oleh EN`, Qwen Base 0.6B, seed 42. Исходный синтез — 54,43 секунды; отдельная копия с ×1,20 и high-pass 60 Hz — 45,34 секунды. Для запаса до true peak -2 dBTP громкость копии установлена в -21,86 LUFS. Локальный ASR восстановил весь текст, нечисловых и full-scale samples нет; reference и принятая короткая F сохранены с проверкой hash. От отправки задания до обнаружения скачанного WAV прошло 377 секунд: это время очереди, синтеза, polling и скачивания, а не чистый замер инференса. Upstream штатно разбивает этот текст на две части. Спокойный рассказ, восклицания и вопросы заданы содержанием и пунктуацией; `instruct` не включался. Узнаваемость на протяжении всей записи, темп и естественность интонаций ожидают прослушивания владельцем. Одинаковый коэффициент ×1,20 не гарантирует одинаковый темп на разных текстах.

Владелец узнаёт свой голос и в длинной пробе, но темп ×1,20 для неё оказался некомфортным. По его запросу в `pilot-004-en-long/listening-002` подготовлена копия на 15% медленнее предыдущей: ×0,85 относительно прослушанной версии, то есть ×1,02 относительно исходного синтеза, 53,34 секунды. Она заново обработана из исходного WAV, с сохранением прежних файлов и громкости -21,86 LUFS; предпочтение по темпу ожидает прослушивания. Короткая принятая F остаётся отдельным примером, а ×1,20 не считается универсальной скоростью для всех текстов. Владелец затем принял замедленную 53-секундную версию как подходящую для теста, отметив монотонную манеру чтения. Паузы и интонации остаются направлением улучшения; пунктуация субтитров сама по себе не меняет уже синтезированную речь.

Подготовлен отдельный развёрнутый русский `pilot-005-ru-long` на принятом ранее профиле `Oleh RU`: 152 слова, Qwen Base 0.6B, seed 42, 62,06 секунды. Для первого прослушивания темп не менялся; применены high-pass 60 Hz и линейная регулировка громкости до -22,07 LUFS с true peak -2 dBTP. Full-scale и нечисловых samples нет. В локальном ASR — четыре операции выравнивания, WER proxy 2,63%; это расхождения распознавания с текстом, а не подтверждённая оценка дикции или сходства. Сохранены исходный синтез, короткая принятая русская проба и reference. Весь вызов генерации занял 313,86 секунды, включая проверку binding, очередь, синтез, polling и скачивание. Узнаваемость, темп, паузы и интонации длинной русской версии ожидают прослушивания владельцем.

Владелец подтвердил очень сильное сходство длинного русского примера со своим голосом и запросил менее «носовую», более плотную окраску. В `pilot-005-ru-long/tone-001` сохранены локальный акустический отчёт и A/B по 16,125 секунды: исходный тембр и творческая проба с EQ 180 Hz +2,5 dB, 1100 Hz -2 dB и мягкой компрессией. Громкость A/B — -22,06/-22,09 LUFS; скорость, высота и форманты не сдвигались, full-scale samples нет. Это вариант для слухового выбора, а не подтверждённое устранение назальности. Отчёт получен движком Praat 6.1.38 через отдельную библиотеку `praat-parselmouth==0.4.7` в `~/.local/share/astel-voice-analysis`; GUI Praat не устанавливался, зависимости Voicebox не менялись. Проверка показала чувствительность оценки F0 к нижней границе поиска; по этим цифрам не оценивается «гундосость», дыхательная опора или привлекательность голоса. Reference, принятые пробы и RAW сохранены. Предпочтение B и сохранение узнаваемости после обработки ожидают прослушивания владельцем. Источники: [Praat Voice](https://www.fon.hum.uva.nl/praat/manual/Voice.html), [ASHA: resonance assessment](https://www.asha.org/practice-portal/clinical-topics/resonance-disorders/).

В A/B владелец предпочёл окраску B. Те же EQ и компрессия применены ко всей русской записи в `pilot-005-ru-long/tone-002-full`: 62,06 секунды, -22,07 LUFS, true peak -4,32 dBTP, full-scale samples нет. Скорость, высота и reference не менялись; исходник сохранён. После прослушивания полной версии владелец предварительно принял её как рабочую основу русского голоса; приёмка остаётся пробной, с последующей оценкой в контексте видео. Это выбранная обработка русской пробы, без автоматического переноса на английский голос или production.

## Где запускаем

| Вариант | Решение |
| --- | --- |
| Mac, Apple Silicon, 16 GB | Stage 1: текущий локальный пилот, один голос и одна генерация за раз. |
| Windows / Kevin | Stage 2, только если измеренная скорость или качество на Mac недостаточны. GPU и драйверы Kevin пока не проверялись. |
| Облачный GPU | Возможный последующий исполнитель той же задачи; сейчас не создаётся и не оплачивается. |

Локальность не обязательное ограничение Voicebox: upstream поддерживает remote backend. Для первого голоса Mac удобнее: образец, профиль и результат находятся на одной машине. После скачивания выбранных весов этот Qwen-путь использует локальный checkpoint; Hugging Face включён в offline mode, Voicebox Cloud выключен. Это настройки приложения, а не сетевой firewall всей ОС.

Схема первого этапа: **собственная запись → профиль Oleh RU / Oleh EN → утверждённый русский или английский текст → WAV и manifest → прослушивание Олегом**. Оба языка входят в пилот. Сначала можно принять узнаваемый голос на русском, затем сравнить английскую речь с тем же reference.

Следующий этап после приёмки: WAV → OpenReel или существующий renderer → проверенный MP4 → существующий Distribution Hub. Автопубликация, GTA6 cast и каналы этим пилотом не меняются.

Решение по нативной интеграции от 27 октября: добавить локальный Voicebox provider в существующую OpenReel Text to Speech и связать его с отдельной фоновой задачей Astel для готового аудио, тайм-кодов, субтитров и нарезки. Сама панель Voicebox/автосборка ещё не реализована. Проверены pinned source и upstream от 17 октября; рабочий submodule и установленный редактор не обновлялись. Обоснование, точки расширения и критерии проверки: [Voicebox integration decision](../openreel/MIGRATION.md#voicebox-integration-decision--2026-10-27), [decision metadata](OPENREEL_INTEGRATION_DECISION.json).

## Что сохранено и изменено

- `vendor/voicebox` — отдельный git submodule upstream, commit `8af7efe62fab8d33e2a5dfbedabaa45f68a5184f`. MIT license сохранена в submodule и `integration/voicebox/LICENSE.voicebox`.
- `integration/voicebox/patches/0001-required-clone.patch` применяется только к отдельной runtime-копии. Upstream submodule не редактируется.
- Qwen MLX требует существующий reference, точный transcript, Base-модель и оба encoder-компонента. Ошибка, несовместимая модель, пустой/нечисловой/полностью тихий результат останавливают генерацию. Генерации без reference в этом пути нет.
- Неподдерживаемый `instruct` завершается ошибкой. Лёгкий естественный акцент проверяем на собственном английском reference, без обещания управлять им одной текстовой командой.
- `src/video_editor/voicebox.py` привязывает один профиль к точному sample/transcript/hash; сохраняет версии WAV, script, request, seed, model identity, audio hash и QA status. Изменение reference выявляется до отправки и при получении результата.
- Повторного HTTP POST при timeout нет. С известным generation ID используется `resume`; без него сначала разбираем историю. Внутри upstream остаются документированные разбиение длинного текста и локальные adaptive retries при нестабильном аудио; seed сам по себе не гарантирует побайтовое воспроизведение.

Изолированный runtime по умолчанию: `~/.local/share/astel-voicebox`. В нём `venv`, pinned source, `data`, `hub`, `models/0.6B`, installed requirements и model receipt. Пути можно перенести целиком через `ASTEL_VOICEBOX_HOME`; старые ASAP окружения не используются. Веса занимают около 2,51 GB и не включаются в Git.

## Запуск на Mac

Из корня этой ветки:

```bash
scripts/setup_voicebox_mac.sh
scripts/start_voicebox_mac.sh
```

Setup требует Python 3.12, использует отдельный venv, устанавливает закреплённые зависимости и скачивает только reviewed 0.6B checkpoint. При необходимости указать Python: `ASTEL_PYTHON=/absolute/path/to/python3.12 scripts/setup_voicebox_mac.sh`. FFmpeg нужен для подготовки reference; на текущем Mac он уже есть.

Во втором терминале:

```bash
scripts/voicebox.sh doctor
```

REST: `http://127.0.0.1:17493`. MCP: `http://127.0.0.1:17493/mcp`. Служба запускается в foreground; остановка — Ctrl+C. Автозагрузка/LaunchAgent не устанавливались. Для повторного запуска после перезагрузки использовать start script. `/health` показывает загруженную модель только после её загрузки; setup сам инференс не запускает.

## Первый личный голос

Записать 30–60 секунд естественной русской или английской речи: один голос, без музыки, без попытки искусственно усиливать акцент. Из записи выбрать чистый фрагмент **10–25 секунд** и записать его дословный transcript. Upstream принимает reference только 2–30 секунд; целую минуту загружать в профиль нельзя.

Ниже имена файлов примера: заменить исходный путь своим. `input/` и `output/` исключены из Git.

```bash
scripts/voicebox.sh prepare-reference \
  --input /absolute/path/oleh-recording.m4a \
  --start 5 --duration 20 --output input/voicebox/oleh-reference.wav

scripts/voicebox.sh register \
  --language ru \
  --reference input/voicebox/oleh-reference.wav \
  --transcript input/voicebox/oleh-reference.txt \
  --binding output/voicebox/oleh-ru.binding.json

scripts/voicebox.sh generate \
  --binding output/voicebox/oleh-ru.binding.json \
  --script input/voicebox/pilot-ru.txt \
  --output output/voicebox/pilot-001
```

`prepare-reference` сохраняет RAW и создаёт отдельный mono PCM WAV 24 kHz. Transcript должен соответствовать выбранному фрагменту. Файл `pilot-ru.txt` содержит текст для новой озвучки, а не transcript образца. `register --language` описывает язык записи. `generate` наследует его; `generate --language en` позволяет проверить английский с русским reference, а `--language ru` — русский с английским. Это выбор языка синтеза, не перевод текста: script должен быть написан на нужном языке. Качество переноса голоса между языками требует слухового теста; для лучшего английского может понадобиться отдельный английский reference. Имена профилей по умолчанию — `Oleh RU` и `Oleh EN`.

Результат: `narration.wav`, `script.txt`, `manifest.json` в новом каталоге версии. `qa_status=awaiting_owner_listening` означает, что технически полученный файл ещё не принят как собственный голос.

При незавершённой известной генерации:

```bash
scripts/voicebox.sh resume --output output/voicebox/pilot-001
```

Не переиспользовать существующий output для другой версии. При `registration_incomplete` или `submission_unconfirmed` проверить сохранённый receipt и историю сервера до новой попытки. WAV/M4A от пользователя можно сначала получить из указанной Drive-папки, затем обработать локально; автоматический Drive watcher пока не настроен.

## Проверка качества и следующие MCP steps

1. Принять один reference и exact transcript; создать отдельный `Oleh RU` или `Oleh EN`.
2. Сравнить короткую речь, числа, имена и 45–60 секунд непрерывного текста на русском и английском. Олег оценивает узнаваемость, понятность речи, акцент и отсутствие артефактов. Замерить время **генерации**, не путать его с загрузкой модели.
3. Если результат слабый, сравнить 1.7B Base или Chatterbox на том же тексте/reference. Они сейчас не установлены; 1.7B не включается как скрытый fallback.
4. Локальный MCP уже проверен: четыре инструмента discovery, успешный `voicebox_list_profiles`. MCP ещё не зарегистрирован как доступный этому чату Voicebox connector. Для подключения локального агента использовать Streamable HTTP URL выше; `X-Voicebox-Client-Id` обозначает клиента и не является паролем.
5. Сначала разрешить READ списка профилей. `voicebox_speak` генерирует и воспроизводит через динамики; для монтажных файлов использовать Astel REST adapter. Whisper/dictation и остальные движки этим минимальным окружением не валидировались.
6. Для облачного чата потребуется отдельный защищённый доступ к Mac. Публичный порт не открывать: upstream remote docs прямо указывают отсутствие API authentication. Туннель, VPN и конфигурацию доступа делать отдельным шагом после голосового теста.

Проверки и их границы: [VALIDATION.json](VALIDATION.json). Источники и причины выбора: [RESEARCH.md](RESEARCH.md).
